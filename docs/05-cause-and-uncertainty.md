# 그래서 원인은 무엇이었을까

[처음으로](../README.md) · [검사 결과](04-validation.md)

지금도 가장 궁금한 부분이다. Windows를 다시 설치해 사용할 수 있게 됐지만, 처음 왜 고장 났는지는 답을 얻지 못했다.

## 부팅을 막고 있던 문제는 찾았다

주 GPT와 보호 MBR이 손상돼 있었고, NTFS 구조에도 수리가 필요한 부분이 있었다. 이를 복구한 뒤에는 파일을 읽을 수 있었지만 Windows는 0x74에서 멈췄다. 이후 DISM도 SAM 레지스트리 하이브를 읽는 단계에서 실패했다.

부팅되지 않는 이유를 설명할 문제들은 실제로 있었다. 다만 이 손상들이 어떤 순서로 생겼고 최초 충돌과 어떻게 이어지는지는 확인하지 못했다. [E01–E03, E07]

## SSD 고장이라고 할 수 있을까

SSD 전체 이미지는 읽기 오류 없이 확보했고, SMART 매체 오류는 0이었다. 짧은 자체 진단도 통과했다.

한편 NVMe 관리 명령 오류와 시간초과 기록은 있었다. 과거 보존 로그에서 1,634건이 확인됐고, 오류 811건과 시간초과 823건으로 나뉘었다. 이 계열 이벤트는 2025년부터 있었다.

새 Windows에서도 같은 형태의 기록이 남았다. 이전 Windows의 손상만으로 설명하기 어려운 단서다. SSD·컨트롤러·펌웨어·드라이버 사이의 동작을 살펴볼 이유는 있지만, 당시 데이터 I/O 집계의 실패 카운터는 0이었다. 관리 명령 이벤트를 실제 데이터 손상의 원인으로 연결할 증거는 없었다. [E02, E10–E12]

## 연결하지 못한 기록들

고장 당일 아침의 Partition 로그에는 정상 파티션 배치가 있었다. 나중에 확보한 이미지에서는 앞쪽 1MiB가 거의 0으로 채워져 있었다. 언제, 어떤 작업으로 바뀌었는지를 보여 주는 기록은 찾지 못했다. 최초 충돌과 후속 복구 과정 중 어느 시점인지도 알 수 없다.

개발 도구를 사용하던 중 고장이 났지만, 그것만으로 해당 프로그램을 원인이라고 할 수는 없다. 읽을 수 있었던 PowerShell 기본 로그의 제한된 검색에서는 파괴적 디스크 명령이 발견되지 않았다. 다만 Operational 로그 하나가 손상돼 읽히지 않아 모든 실행 경로를 확인한 것은 아니다.

9월 초에는 Hello/PIN 문제가 있었지만 그 뒤 컨테이너 읽기 성공 기록이 이어졌다. 이 인증 문제와 이후 디스크 손상이 같은 원인이라는 연결도 찾지 못했다. [E02–E04]

## 복구 USB의 오류는 별도였다

ASUS 복구 USB에서 나온 0xD1/nwifi.sys는 Wi-Fi 연결 과정에서 발생했다. SSD에 있던 기존 Windows의 0x74와는 환경도 시점도 달랐다.

복구 USB의 충돌 덤프와 호출 스택은 확보되지 않았다. 그래서 무선랜 칩이나 특정 드라이버 자체의 결함까지 판단할 수 없었다. [E08]

## 조사할 수 있었던 범위

보존된 조사 기록에는 진단 파일 693개, EVTX 263개, WER 383개, DMP 13개가 있었다. System 이벤트 38,916개를 읽었고 선택한 38개 로그에서 56,564개 이벤트를 추출했다. WER는 실제 발생 시각과 ID를 대조해 378개 보고로 구분했다.

덤프에는 이전 날짜의 장애와 중복 사본이 섞여 있었다. 모든 덤프를 WinDbg로 완전 분석한 것은 아니고, 최초 장애에 해당하는 새 커널 덤프도 확인되지 않았다. 당시 다시 보고된 GPU 오류의 실제 발생일이 이전 달인 경우도 있었다. [E02, E03]

## 중간에 바꾼 판단

| 처음 보인 결과 | 다시 확인한 내용 |
|---|---|
| 레지스트리 로드 검사 실패 | 정상 대조군까지 실패했다. 노트북 WinRE에서는 사본 로드에 성공했다. |
| Storport 로그가 비어 있음 | 읽기 권한 문제였다. 관리자 조회에서는 오류가 확인됐다. |
| 메모리 검사가 끝난 것 같음 | 내 기억이 불확실했고 완료 이벤트도 없어 미확인으로 남겼다. |
| Healthy/OK 표시 | 기본 상태값만으로 간헐적인 부품 문제까지 배제할 수는 없었다. |

현재까지 부품 고장은 검출되지 않았다. 새 Windows와 필요한 드라이버로 사용 환경도 회복했다. 남은 의문은 기록해 두고, 추가 극한 검사 대신 평소처럼 사용하기로 했다.
