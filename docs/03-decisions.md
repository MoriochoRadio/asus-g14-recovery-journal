# 복구 중 내린 결정들

[처음으로](../README.md) · [복구 과정](02-recovery-journey.md)

복구 중에는 여러 번 선택해야 했다. 기존 환경을 더 살려 볼지, 다른 방법으로 넘어갈지, 이제 그만 점검하고 써도 될지. 당시 무엇을 보고 결정했는지 따로 모았다.

## 초기화 전에 이미지를 남겼다

Windows가 부팅되지 않아도 자료는 필요했다. 전체 SSD 이미지를 확보한 덕분에 이후 복구가 잘못되거나 새로 설치하더라도 보존본을 남길 수 있었다.

백업 GPT를 복원할 때도 같은 생각이었다. 읽을 수 있는 표가 있다는 사실만으로 쓰기보다, 고장 당일 로그의 파티션 배치와 먼저 비교했다.

## 레지스트리 후보는 적용하지 않았다

구조 검사를 통과한 후보가 있었고 WinRE에서도 로드됐다. 하지만 원본과 로그 사이에 빠진 시퀀스가 있었다. 정상 부팅을 확인한 후보도 아니었다.

기존 SYSTEM을 이 후보로 교체하는 단계까지는 가지 않았다. 별도 사본 검사 결과를 남긴 채 다른 복구 가능성을 살펴봤다.

## 재설치는 자료를 확보한 뒤 결정했다

GPT 복원으로 파티션이 보였고, NTFS 수리로 파일 접근도 돌아왔다. 그 뒤에는 레지스트리와 시스템 검사에서 다시 막혔다.

기존 환경을 유지하고 싶었지만 금요일부터 토요일까지 이어진 작업으로 지친 상태였다. 필요한 자료는 이미 확보했으므로, 계속 같은 Windows를 살리는 것보다 새로 설치해 사용하는 쪽을 선택했다.

## 설치 파일보다 현재 장치 상태를 먼저 봤다

| 항목 | 결정한 이유 | 결과 |
|---|---|---|
| Armoury 제어 인터페이스 | 현재 1.2.0.2, 준비 파일은 1.2.0.1 | 현재 버전 유지 |
| 카메라 확장 | 최신 패키지의 지원 장치 ID가 실제 카메라와 다름 | 설치하지 않음 |
| BIOS | 현재 310, 당시 공식 최신도 310 | 같은 버전 재설치 보류 |
| OEM SSD 펌웨어 | 정확히 적용 가능한 공식 업데이트를 확인하지 못함 | V8MA000 유지 |
| Parade HID | 실제 누락 장치 ID와 일치 | 설치 후 문제 장치 해결 |
| Radeon | 장치 ID·서명·해시 확인 | 공식 패키지 적용 |

Radeon 설치 뒤에는 동봉 Crash Defender 버전이 25.20.0.4에서 25.10.0.4로 바뀌기도 했다. 원하지 않은 버전 변화도 실제 결과이므로 남겼다. 재부팅 후 Windows Update에서 더 높은 버전을 다시 제공하지 않아 강제로 바꾸지는 않았다.

## 완료 여부는 다시 확인했다

AURA 업데이트를 눌렀을 때 앱이 닫혔지만 설치 버전은 0.0.21이었다. 나중에 0.0.60으로 바뀐 것을 확인하고 기록을 갱신했다.

로그도 마찬가지였다. Storport 결과가 비어 있어 오류가 없다고 생각했지만, 실제로는 읽을 권한이 없었다. 관리자 권한으로 다시 조회하자 이벤트가 나왔다.

Armoury에서는 성능 모드를 선택했는데 Windows 전원 구성표가 Turbo로 남아 있었다. 최종적으로 Windows 모드를 선택한 뒤 균형 조정이 활성화된 것을 확인했다.

## 추가 부하 검사는 하지 않기로 했다

시스템·SSD·MyASUS 검사 결과는 양호했고 사용을 중단해야 할 고장은 확인되지 않았다. 더 오래 검사하는 방법은 있었지만, 다시 일상적으로 쓰는 것이 우선이었다.

메모리 오프라인 검사와 일부 실제 동작 확인은 미완료로 남겼다. 검사하지 않은 것을 정상이라고 적는 대신, 필요할 때 이어서 확인할 수 있도록 정리했다.

관련 검사값과 버전은 [재설치 후 점검](04-validation.md), 각 단계의 자료는 [참고 기록](../evidence/README.md)에 있다.
