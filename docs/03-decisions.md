# 의사결정 기록

[처음으로](../README.md) · [복구 여정](02-recovery-journey.md)

결과가 좋았는지만으로 당시의 판단을 평가하지 않기 위해, 선택 당시의 근거와 보류한 행동을 같이 기록했습니다.

| 결정 | 당시 근거 | 실행·결과 | 남은 한계 |
|---|---|---|---|
| 새 설치 전에 데이터 보존 | Windows 접근 불가, 원본 상태가 중요 | 전체 SSD 이미지와 우선 자료 확보 | 읽기 성공이 논리적 무결성은 아님 |
| 백업 GPT를 활용 | 고장 당일 파티션 로그와 일치 | 파티션 인식 복원 | 최초 변조 시각·주체 미확정 |
| NTFS 수리 진행 | 암호화 잠금 해제 후에도 구조 오류 | 파일 접근 회복 | Windows 부팅은 실패 |
| 레지스트리 후보를 곧바로 덮어쓰지 않음 | 시퀀스 간격, 구조 검사와 부팅 검증의 차이 | 사본 로드 검사만 수행 | OS 전체 일관성 미확인 |
| 새 Windows 설치로 전환 | 백업 확보, 다층 손상, 복구 시도 한계, 사용자 피로 | 사용자 승인 후 진행 | 최초 원인 규명과는 별개 |
| ASUS Wi-Fi 복구 반복 중단 | 같은 환경에서 충돌, 새 설치 완료 증거 없음 | Microsoft USB로 경로 변경 | USB 충돌의 정확한 드라이버 원인 미확정 |
| 실제 호스트·디스크부터 식별 | 초기 도구 호스트와 대상 노트북이 달랐음 | GA403UM 및 내부 SSD 확인 | 드라이브 문자·번호를 다음 환경에 고정 적용하면 안 됨 |
| 현재 앱·드라이버를 먼저 조사 | 사용자가 이미 설치, 준비물은 이전 버전 가능 | 중복 설치·의도적 강제 다운그레이드 방지 | 패키지 동봉 구성요소는 따로 변화 확인 필요 |
| BIOS 310 재설치 보류 | 현재·공식 지원 버전 동일 | WU의 같은 펌웨어 항목 제외 | 보류는 펌웨어 결함 배제와 다름 |
| 최신 카메라 패키지 미설치 | 실제 하드웨어 ID 불일치 | 기존 정상 열거 드라이버 유지 | 영상·얼굴 로그인 실제 동작 미확인 |
| 권한 없는 빈 로그 결과 철회 | 관리자 전용 채널 접근 거부 확인 | UAC 후 다시 수집, 이벤트 존재 확인 | 도구 실패와 장비 상태를 구분해야 함 |
| 최종 Windows / 균형 조정 모드 | Armoury 성능 표시와 활성 Turbo 구성표 차이 | Windows 모드 선택 후 균형 조정 확인 | 앞선 표시 불일치의 원인 미확정 |
| 추가 극한 부하 검사 중단 | 기본·일부 상세 검사 양호, 사용자 부담과 의사 | 일상 사용 재개 선택 | 장기 안정성·미실행 검사는 미확인으로 유지 |
| 경험을 공개 기록으로 전환 | 사용자 요청: 시도와 여정을 의미 있는 경험으로 남기기 | 원본 대신 검토된 비식별 문서 작성 | 전체 포렌식 자료 공개·전수 분석과는 다름 |

## 승인과 역할

사용자가 데이터 보존, 원본 삭제·새 설치, 실제 UAC·재부팅, 공개 저장소 생성 여부를 결정했습니다. 에이전트는 범위 안에서 상태 수집·공식 패키지 검증·선별 설치·결과 분석을 수행했습니다.

설치 완료를 사용자에게서 들은 것과 도구로 버전을 확인한 것은 별도 근거입니다. 화면에서 업데이트를 눌렀다는 사실도 실제 설치 버전 확인과 같지 않습니다. AURA 업데이트를 처음 시도한 뒤에는 0.0.21이 남아 있었으므로 성공으로 처리하지 않았고, 재부팅 이후 0.0.60을 확인한 시점에 설치 상태를 갱신했습니다.
