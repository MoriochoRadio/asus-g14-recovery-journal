# 회고 — 고장을 고치는 과정에서 배운 것

[처음으로](../README.md) · [의사결정](03-decisions.md)

이 글은 사용자 발언과 작업 기록을 바탕으로 정리한 회고입니다. 사용자가 직접 쓰지 않은 감정이나 전문성을 1인칭 경험담으로 만들어 넣지 않았습니다.

## 이 기록을 남기는 이유

사용자는 고장 후의 시도와 여정을 전부 정리해 GitHub에 남기고 싶다고 했습니다. 복구가 끝났다는 한 줄보다, 실패를 지나 어떤 판단으로 다음 단계에 도달했는지가 의미 있는 경험이기 때문입니다.

이 과정에는 명령 실행 외의 일도 많았습니다. 자료를 보존하고, 실제 장비에서 화면과 대상을 확인하고, 수리를 계속할지 초기화할지 결정하고, 여러 차례의 재부팅과 인증 조작을 수행해야 했습니다. 해결되지 않는 상태에서 시간을 들여 판단을 이어간 것도 사건의 일부입니다.

## 실제로 경험한 기술적 판단

| 경험 | 이번 사례의 구체적인 내용 |
|---|---|
| 데이터 보존 우선순위 | 원본 이미지 확보 후 복구·초기화 결정 |
| 저장장치 구조 이해 | GPT 인식, NTFS 접근, Windows 부팅이 서로 다른 단계임을 확인 |
| 증거 대조 | 백업 GPT와 과거 파티션 로그를 비교 |
| 검사 신뢰성 판단 | 정상 대조군 실패, 권한 거부, 인코딩 오류를 구분 |
| 공식 배포 검증 | 설치 미디어·드라이버의 출처, 서명, 해시, HW ID 확인 |
| 실제 적용 검증 | 앱 버전과 드라이버 버전, 패키지와 구성요소 버전을 분리 |
| 상태 인수인계 | 변경 전·후와 재부팅 전 기록을 파일로 남김 |
| 불확실성 관리 | 확정된 손상과 원인 가설을 구분, 미확인을 통과로 바꾸지 않음 |

이것은 독립적으로 모든 도구를 개발하거나 모든 덤프를 완전 분석했다는 경력이 아닙니다. 사용자와 AI 도구의 협업으로 수행한 복구 사례이며 역할과 검사 범위를 공개한 기록입니다.

## AI 도구를 사용하면서 배운 점

AI의 설명도 근거와 대조해야 했습니다. 일반 상태의 Healthy/OK만으로 하드웨어 고장을 배제하거나, 오류 코드 한 개를 최초 원인으로 지목하는 설명은 신뢰 범위를 넘어섭니다.

이번 작업에서도 Storport 빈 결과를 잘못 해석했다가 권한 제한을 확인하고 정정했습니다. 명령 종료 코드, 실제 로그 본문, 정상 대조군, 적용된 버전을 함께 확인하는 과정이 중요했습니다. 잘못된 중간 설명을 삭제해 매끄러운 성공담으로 만들기보다, 어떻게 바로잡았는지를 남겼습니다.

AI가 준비하고 실행한 부분은 AI 지원으로 명시합니다. 사용자의 결정·현장 조작·검증 참여를 생략하지 않는 것도 같은 이유입니다.

## 시간을 쓰는 것과 문제를 푸는 것은 다르다

사용자는 긴 복구 작업으로 지쳤고, 같은 질문과 사진 요청의 반복을 줄여 달라고 했습니다. 보증 만료가 가까워 불안했지만 센터 방문에 드는 시간과 비용도 부담이었습니다.

모든 불확실성을 없애려고 검사를 끝없이 늘리는 것은 사용자의 목표와 맞지 않았습니다. 충분히 검증된 부분과 미확인을 구분한 뒤, 어느 시점에서 일상으로 돌아갈지 정하는 것도 복구의 의사결정입니다.

재설치 후 더 긴 SSD 검사, 오프라인 메모리 검사, CPU/GPU 부하 검사 등의 가능성을 논의했습니다. 그러나 사용자에게 극한 테스트가 필수인 것처럼 전달해서는 안 됐습니다. 실제 고장이 검출되지 않은 현재 결과와 사용자의 의사를 고려해 추가 부하 검사를 진행하지 않았습니다.

## 자가 복구의 의미와 한계

백업을 확보한 상태에서 공식 Windows를 새로 설치한 것은 사용 환경을 회복하기 위한 합리적인 선택이었습니다. 기록상 그 재설치가 부품을 손상시켰다는 증거는 없습니다.

동시에 클린 설치는 물리적인 부품을 새것으로 만들지 않습니다. “깨끗한 Windows”와 “장기 무고장이 검증된 하드웨어”는 다른 주장입니다. 이 차이를 이해한 상태에서 일상 사용을 재개했습니다.

사용자가 말한 11월 보증 만료는 당시 우려로 기록합니다. 이 저장소에서 정확한 보증 종료일이나 무상 수리 자격을 확인·보장한 것은 아닙니다. 센터 방문은 실제 증상·검사 결과·시간과 비용을 고려할 선택지로 남겼고, 방문했다는 기록은 없습니다.

## 포트폴리오에 담을 수 있는 설명

> 개인 노트북의 부팅 불능 상황에서 AI 도구와 협업해 데이터 보존, GPT·NTFS·Windows 구성 문제의 단계별 조사, 공식 설치 미디어 검증과 재설치 후 상태 검증을 수행했다. 실패한 시도와 검사 한계를 함께 기록하고, 초기 원인이 미확정인 상태에서 사용 환경 회복과 일상 복귀의 기준을 정리했다.

“SSD 고장 원인을 완전히 규명했다”, “하드웨어 무결성을 입증했다”는 표현은 현재 증거에 맞지 않습니다. 이 기록의 강점은 완벽한 성공을 주장하는 대신 판단의 근거와 한계를 독자가 따라갈 수 있게 하는 데 있습니다.

## 앞으로의 기록

새 증상이 실제로 생기면 발생 시각, 사용 환경, 재현 여부, 새 검사 결과를 추가합니다. 아무 증상이 없는데 매일 오류 로그를 뒤지거나 부하 검사를 반복하는 것을 유지 관리 목표로 삼지 않습니다. 중요한 파일의 백업과 정상적인 일상 사용을 이어갑니다.
