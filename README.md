# ASUS G14 복구 기록 — 고장 이후 다시 일상으로

**2026년 9월 18–19일, 부팅되지 않던 노트북을 복구하고 그 판단 과정을 남긴 개인 기술 기록입니다.**

ASUS ROG Zephyrus G14 GA403UM을 사용하던 중 오류 화면이 나타났고, 이후 Windows로 돌아오지 못했습니다. 데이터를 보존하고 기존 환경을 살리려고 시도했지만, 파티션·파일시스템·Windows 구성 문제를 차례로 마주했습니다. 최종적으로 Microsoft 공식 설치 미디어로 Windows를 새로 설치하고 필요한 드라이버와 기능을 검증했습니다.

이 기록의 목표는 “고장을 완벽하게 해결했다”는 결론을 만드는 것이 아닙니다. 어떤 증거를 모았고, 어떤 시도가 어디까지 효과가 있었으며, 왜 복구 방향을 바꾸었는지를 남기는 것입니다. 최초 장애의 정확한 촉발 원인은 아직 확정하지 못했습니다.

> **최종 상태:** 새 Windows로 부팅·사용 환경 회복. 검사 범위에서 확정된 부품 고장 없음. NVMe 관리 명령 이벤트와 일부 미검증 항목은 남아 있음. 추가 극한 부하 검사를 진행하지 않고 일상 사용으로 돌아가기로 결정.

## 확인한 성과와 남겨 둔 문제

- 전체 SSD 이미지 읽기 완료: ddrescue 기록상 100%, 읽기 오류 0.
- 백업 GPT와 기존 Windows의 파티션 기록을 대조한 뒤 파티션 인식 복원.
- NTFS 수리 후 파일 접근 회복. 기존 Windows 부팅은 여전히 실패.
- Microsoft 설치 USB 제작·검증 후 새 Windows 로그인 성공.
- 누락 장치 드라이버 해결: 문제 장치 1개 → 0개.
- 새 OS의 DISM ScanHealth 및 SFC verifyonly 검증 완료.
- SSD 짧은 자체 검사 통과, MyASUS 자동 진단 문제 0개.
- 재부팅 후 드라이버 유지, 일상용 Windows 모드 / 균형 조정 확인.
- NVMe 관리 명령 오류의 원인, 오프라인 메모리 검사 완료, 일부 실제 주변장치·절전 동작은 미확인.

이 결과는 조사 당시의 상태입니다. 장기 무고장이나 모든 부품의 정상성을 보증하는 진단서는 아닙니다.

## 기록의 작성 방식

사용자가 실제 장비 조작, 복구 방향과 초기화 결정, 일상 복귀 여부를 결정했습니다. AI 도구는 로그 분석, 공식 자료 확인, 명령·스크립트 준비, 허용된 로컬 점검과 문서 정리를 도왔습니다. 이전 단계는 인수인계 및 보존된 조사 기록을 근거로 재구성했습니다. 이 저장소 작성 시 원본 1TB 이미지나 모든 과거 대화를 다시 전수 조사한 것은 아닙니다.

“실행함”, “사용자가 보고함”, “제안만 함”, “미확인”을 구분했습니다. 대화에서 과도하게 단정한 설명이나 권한 부족 때문에 잘못 해석했던 결과도 정정 기록에 포함했습니다.

## 공개와 재사용

이 저장소에는 비식별 문서와 선별된 검사 수치만 있습니다. 원본 로그·덤프·레지스트리·사진·복구 이미지·개인 파일·설치 바이너리는 포함하지 않습니다. 과거 복구 명령은 다른 컴퓨터에서 따라 실행할 수 있는 자동 수리 스크립트로 제공하지 않습니다.

문서는 AI의 도움으로 정리한 개인 사례 기록입니다. ASUS·Microsoft의 공식 진단 문서가 아니며, 별도의 재사용 라이선스는 아직 지정하지 않았습니다.
